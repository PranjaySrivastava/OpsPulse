# 📄 Product Requirements Document (PRD)
## Project: OpsPulse — Autonomous SRE & Real-Time Incident War Room
### Hackathon: Zero to Chat (CometChat Hackathon)

---

### 1. Executive Summary
**OpsPulse** is an intelligent, mission-critical incident response platform that turns real-time communication into an automated remediation command center. When production outages or system alerts occur, OpsPulse leverages the **CometChat Model Context Protocol (MCP)** to automatically provision a dedicated **Incident War Room**, invite on-call engineers, and launch an active **AI SRE Agent** into the channel.

Powered by **CometChat’s real-time messaging, presence, and WebRTC emergency calling SDK**, along with **OpenRouter’s automated free-tier AI model failover chain** (`LLaMA 3.3 70B:free`), engineering teams can collaborate in real time, jump on an instant 1-click voice/video triage huddle, review diagnostic Git diffs generated by the AI SRE, and trigger hotfixes or rollbacks directly through interactive cards embedded in the chat stream.

---

### 2. Problem Statement
- **Fragmented Incident Triage**: During high-severity outages (P1/P2), engineers waste 15–20 minutes jumping between PagerDuty alerts, Slack channels, Zoom meetings, AWS consoles, and terminal logs.
- **Context Loss & High MTTR**: Critical incident context is scattered. On-call engineers scramble to correlate error traces with recent Git commits while managing panicked team communication.
- **Passive AI Chatbots**: Existing AI tools are passive chatbots that wait for prompts instead of proactively streaming diagnostics, proposing concrete Git patches, and executing remediation actions in the room.

---

### 3. Target Audience & Personas
1. **On-Call Software Engineers**: Triage production failures under stress; need instant context, diagnostic logs, and proposed patches without leaving the chat.
2. **SRE & DevOps Leads**: Coordinate incident response, monitor system health, jump on immediate voice huddles, and approve hotfix deployments.
3. **Engineering Managers & Tech Leads**: Need transparent visibility into incident resolution timelines, MTTR metrics, and automated post-mortem documentation.

---

### 4. Key Value Proposition & "Why It Wins"
- **High-Stakes Enterprise Scenario**: Elevates CometChat from a casual messaging tool to an indispensable, mission-critical incident command center.
- **Deepest CometChat MCP Integration**: The CometChat MCP server is not just a demo gimmick; it is the **automated trigger engine** that provisions incident rooms, configures permissions, and seeds diagnostic payloads from the terminal or alert webhooks.
- **Full CometChat Capability Showcase**: Employs real-time WebSockets, typing indicators, presence, read receipts, and **WebRTC voice/video calling for emergency engineering huddles**.
- **100% Free AI Infrastructure**: Uses OpenRouter's free-tier failover chain (`meta-llama/llama-3.3-70b-instruct:free` as primary) to deliver flagship-tier code reasoning and Git diff generation with zero API cost.

### 6. Functional Requirements

#### 6.1 Incident Room Auto-Provisioning & Onboarding
- **FR-1.1 Automated MCP Room Generation**: Support terminal and alert-driven creation of dedicated incident channels (e.g. `#inc-502-auth-outage`, `#inc-db-pool-exhausted`) via the CometChat MCP connector.
- **FR-1.2 Fast On-Call Switcher**: One-click demo login for key responder roles: `alex_oncall` (Primary Responder), `sarah_lead` (SRE Lead), and `ai_sre_bot` (Autonomous SRE Agent).
- **FR-1.3 Real-Time Presence & Roster**: Live visual status of which engineers are active, in the war room, or on the voice huddle.

#### 6.2 Real-Time Incident Stream (CometChat Core)
- **FR-2.1 Diagnostic Alert Seeding**: Immediate posting of incident severity badge (`P1 - CRITICAL`), error payload, failing service, and impacted user metrics upon room creation.
- **FR-2.2 Real-Time Messaging & Status**: Bi-directional messaging between responders with typing indicators ("Alex is typing…") and read receipts (`✓✓`).
- **FR-2.3 Incident Timeline Log**: Chronological audit trail of all messages, diagnostics, and deployment actions.

#### 6.3 Autonomous AI SRE Copilot (OpenRouter Free Tier)
- **FR-3.1 Automated Root Cause Analysis**: AI SRE analyzes stack traces, correlates with recent git commits, and identifies root causes.
- **FR-3.2 Interactive Git Patch Cards**: Formats proposed fixes into syntax-highlighted Git diff cards with interactive buttons:
  - `[ 🚀 Approve & Deploy Hotfix ]`
  - `[ ⏪ Rollback Recent Commit ]`
  - `[ 🔍 Run Diagnostics ]`
- **FR-3.3 In-Room SRE Commands**: Responders can type `@SRE <query>` or trigger quick action chips (`/diagnose`, `/rollback`, `/postmortem`).
- **FR-3.4 1-Click Post-Mortem Generator**: Executing `/postmortem` instantly produces a formatted Markdown post-incident report with executive summary, timeline, root cause, and preventative action items.

#### 6.4 Emergency Audio/Video War Room (CometChat Calling)
- **FR-4.1 1-Click Emergency Call**: Prominent "Join Audio War Room" / "Video Call" button in the incident header.
- **FR-4.2 Incoming Huddle Alert**: Real-time notification chime and modal allowing responders to join the WebRTC session instantly.
- **FR-4.3 In-Call Controls**: Mute microphone, toggle camera, view active speakers, and disconnect.

---

### 7. Non-Functional Requirements
- **Performance**: Real-time message latency < 200ms; AI SRE patch response < 3s via OpenRouter free model.
- **Reliability & Failover**: Automatic fallback across free models (`llama-3.3-70b:free` → `llama-3.1-8b:free` → `gemini-2.0-flash:free`) so incident triage never halts.
- **Design & A11y**: Strict compliance with Vercel Web Interface Guidelines (`color-scheme: dark`, high-contrast `:focus-visible`, compositor-only motion, `prefers-reduced-motion` killswitch).
- **Security**: All API keys (`OPENROUTER_API_KEY`, `COMETCHAT_API_KEY`) isolated in backend `.env`; clients use public auth tokens only.

---

### 8. Out of Scope for Hackathon Submission
- Production Kubernetes cluster agent installations (simulated realistic webhook alerts used for demonstration).
- Paid PagerDuty API webhooks (built-in simulator provided for live demo).
